# PermitPortal

**A reference architecture for state business one-stop portals.**

Many US states run a partial "business one-stop" portal. Many others offer a registration page and
nothing more. They fail the same way: each agency owns its own form, and nobody owns the dependency
order between them. A business owner who wants to open a shop can find every individual requirement
and still not know what to do first.

PermitPortal specifies a system that resolves a plain-language business description into an **ordered
graph of the credentials that business must obtain** — with a citation on every obligation, a
deterministic engine deciding every determination, and a language model nowhere near the decision.

## The thesis

> Do not make the industry code the primary key of the compliance engine. Make it a derived,
> vintage-stamped projection over a canonical model of the business, and key obligations to the
> attributes that regulations actually test.

Three consequences follow, and they shape everything in this repository:

1. **A code hit proves inclusion; a code miss proves nothing.** Applicability is a boolean expression
   tree over typed predicates — chemical quantities, headcount, equipment, jurisdiction — where the
   industry code is one leaf among several.
2. **Missing input is UNKNOWN, never false.** A rule that cannot be evaluated returns INDETERMINATE
   and a list of what to ask next. In a compliance product, a false negative is the harm.
3. **The model proposes; the engine decides.** Classification produces a *ranked candidate set for
   human confirmation*. An unconfirmed code cannot reach a determination — to be enforced by a
   database constraint, specified in the model today and landing with the first migration.

The specification is **executable**. `spec/model/` is the LinkML source of truth; JSON Schema, SHACL,
Postgres DDL, Pydantic, and TypeScript are generated from it and diff-gated in CI. `spec/rules/`
holds obligations as validated, cited, effective-dated data — CI checks the credential graph for
cycles, verifies every predicate against the attribute registry at the declared scope, and rejects any
rule without a public source.

## Status

This repository is honest about what exists. Every directory carries a `status` in its README, and CI
fails if this table disagrees with them.

| Area | Status | What it is |
| --- | --- | --- |
| [`docs/`](docs/) | `specified` | Problem, domain model, DSL, AI layer, eval methodology, ADRs |
| [`spec/`](spec/) | `specified` | LinkML model, rules, code lists, OpenAPI — the source of truth |
| [`packages/`](packages/) | `scaffolded` | Evaluator contract and the golden correctness cases the resolver runs |
| [`services/`](services/) | `scaffolded` | Resolver (Go) implemented and under test; classifier (Python) not started |
| [`apps/`](apps/) | `scaffolded` | Reference UI |
| [`eval/`](eval/) | `scaffolded` | Harness, synthetic fixtures, committed baselines |
| [`data/`](data/) | `scaffolded` | Public reference data with provenance |
| [`infra/`](infra/) | `scaffolded` | Terraform, modular, deploys from the gcloud CLI |
| [`scripts/`](scripts/) | `implemented` | Repository tooling — clean-room scanner, status checker |

`specified` means decided and written down. `scaffolded` means the shape exists and the contract is
defined. `implemented` means it runs.

## Provenance

Every substantive claim in this repository traces to a public source registered in
[`docs/03-source-register.md`](docs/03-source-register.md) — federal regulatory text via eCFR and GPO
bulk XML, Census classification and concordance files, published accuracy benchmarks, and the
Credential Transparency Description Language. Fixture data is synthetic, generated by a committed
seeded script.

Enforced rather than promised: an external statistic without a resolving `[SRC-nn]` fails CI, rules
without a `source_url` cannot be merged, and a scanner runs over the full tree on every pull request.
The statistics gate is narrow by design and says so. See [`docs/clean-room.md`](docs/clean-room.md).

## Contributing

Single maintainer, but the process is real: one decision per ADR, one ADR per pull request, and CI
gates that block merges — and the repository is explicit about which of its rules are enforced today
versus specified for when the code exists. See [`CONTRIBUTING.md`](CONTRIBUTING.md) and [`AGENTS.md`](AGENTS.md) — the
latter is the constraint file for both humans and AI agents, and it is worth reading as an artifact in
its own right.
